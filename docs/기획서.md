## 0. 한 줄 요약

**"풀수록 격투 지식이 쌓이는 퀴즈 서비스."**
MMA·복싱·킥복싱/무에타이·주짓수·레슬링 등 격투 스포츠 전반의 문제를 AI가 꾸준히 만들고, 사용자는 짧은 퀴즈로 놀면서 해설·지식카드로 배운다. 한국 먼저, 이후 글로벌.

두 목표의 관계:

| 목표 | 사용자 입장 | 서비스 입장 |
|---|---|---|
| [1] 재미 퀴즈 | 데일리 퀴즈, Fight IQ 테스트, 랭킹, 결과 공유 | **유입과 재방문** |
| [2] 지식 확장 | 문제마다 해설, 지식카드, 용어사전, 종목 입문 코스 | **체류와 신뢰** ("퀴즈 앱"이 아니라 "격투 지식 서비스") |

두 목표를 하나로 묶는 설계가 이 기획의 핵심이다. **문제를 바로 만들지 않고 "검증된 사실(Fact)"을 먼저 쌓은 뒤 그 사실로 문제를 만든다** (§6). 쌓인 사실은 그대로 학습 콘텐츠, 해설, 번역의 기반이 된다.

## 1. 서비스 개요

### 1-1. 타깃 사용자

| 페르소나 | 특징 | 원하는 것 | 주 모드 |
|---|---|---|---|
| **라이트 팬** | 큰 대회·유명 선수 위주로 봄, 정찬성·김동현 정도는 앎 | 가볍게 재미, 친구와 비교 | 데일리 퀴즈, Fight IQ 테스트 |
| **코어 팬** | UFC 넘버링 다 챙겨 봄, 커뮤니티 활동 (격갤·에펨 등) | 자기 지식 과시, 랭킹 | 타이틀전(랭크), 고난도 |
| **수련자** | 체육관에서 주짓수/복싱/MMA 수련 | 규칙·기술 이해, 다른 종목 공부 | 종목 입문 코스, 용어사전 |
| **입문자** | 막 보기 시작함 | "판정이 왜 저래?" 같은 기본 궁금증 해결 | 학습 코스, 쉬운 난이도 |

### 1-2. 차별점

1. **종목을 넓게 다룬다**: UFC 퀴즈는 흔하지만, MMA와 뿌리가 같은 종목(레슬링·주짓수·무에타이·복싱·유도·삼보)까지 엮은 곳은 드물다.
2. **해설이 본체다**: 정답/오답보다 "왜 그런지"가 남는다. 틀린 문제가 학습으로 이어진다.
3. **국내 맥락**: 한국 선수, 로드FC, 국내 중계 용어·표기를 기본으로 한다.
4. **콘텐츠가 계속 새로 쌓인다**: AI 파이프라인이 매일 새 문제를 공급하므로 "다 풀어서 끝"이 없다.

## 2. 브랜딩 컨셉

격투 용어로 모드 이름과 등급을 짓는다. 팬에게는 바로 와닿고, 번역해도 의미가 유지된다.

| 요소 | 이름 | 설명 |
|---|---|---|
| 데일리 퀴즈 | **오늘의 5라운드** | 매일 전원에게 같은 5문제, 라운드마다 판정 연출, 결과 공유 |
| 연습 모드 | **스파링** | 종목·주제·난이도를 골라 자유롭게 풀이, 점수 영향 없음 |
| 랭크 모드 | **타이틀전** | 레이팅이 걸린 10문제 세트 |
| 서바이벌 | **논스톱** | 3번 틀리면 KO, 연속 정답 기록 |
| 진단 테스트 | **Fight IQ 테스트** | 20문제로 종목별 강약점 진단 → IQ 점수 + 유형 결과카드 (바이럴용) |
| 등급 | **벨트** | 화이트 → 블루 → 퍼플 → 브라운 → 블랙 (주짓수 벨트 차용), 레이팅 구간에 연동 |
| 오답노트 | **코너** | 틀린 문제를 해설과 함께 다시 보는 곳 ("코너에서 세컨드의 조언") |

Fight IQ 테스트 결과 예시:
> **Fight IQ 132 · 퍼플 벨트**
> 유형: **그래플링 브레인** — 주짓수·레슬링 상위 8%, 복싱 역사는 보강 필요
> (종목별 레이더 차트 + "친구에게 도전장 보내기" 버튼)

## 3. 기능 정의

### 3-1. MVP (첫 출시)

| 기능 | 내용 |
|---|---|
| 오늘의 5라운드 | 매일 0시(KST) 공개, 1일 1회, 결과 공유 이미지(OG 카드) |
| 스파링 | 종목·주제·난이도 필터 후 10문제씩 |
| Fight IQ 테스트 | 20문제 적응형(맞히면 어려워짐), 결과카드 공유 |
| 해설 | 모든 문제에 해설 + 출처 링크 + "관련 지식카드" |
| 비회원 플레이 | 가입 없이 바로 시작, 기록은 브라우저에 저장 → 로그인 시 이전 |
| 로그인 | 구글 (Firebase). 카카오는 이후 |
| 문제 신고 | "정답이 틀렸어요 / 정보가 오래됐어요 / 문제가 애매해요" 3지선다 + 메모 |
| 관리자 검수 화면 | AI 생성 문제의 검수 큐, 신고 처리, 문제 수정·비공개 |

### 3-2. v1 (출시 후 1~2개월)

- 타이틀전(랭크) + 레이팅 + 벨트, 주간/월간 랭킹
- 논스톱(서바이벌)
- 코너(오답노트), 스트릭(연속 출석)
- **지식 라이브러리**: 기술·규칙·단체·용어 지식카드 모음, 검색 (§3-3)
- 종목 입문 코스: "주짓수 처음 보는 사람을 위한 10단계" 같은 순서형 학습 (카드 → 확인 퀴즈)

### 3-3. 이후

- **이벤트 시즌 퀴즈**: 큰 대회 주간에 출전 선수 관련 프리뷰 퀴즈 (가장 강력한 재방문 계기)
- 친구 대결 (같은 문제 세트로 비동기 대결, 링크 공유)
- 사용자 문제 제출 → AI 검증 → 검수 → 게시 (제출자 크레딧)
- 체육관용: 관장이 관원 그룹을 만들고 그룹 랭킹 (B2B 가능성)
- 이미지·영상 기반 문제 (저작권 정리 후. 직접 그린 기술 일러스트 등)
- 앱 (PWA로 시작, 수요 확인 후 네이티브)

## 4. 콘텐츠 체계

### 4-1. 분류 축

문제 하나는 **종목 × 주제 × 난이도 × 시의성 × 지역**으로 분류한다.

**종목 (sport)**

| 코드 | 종목 | 비고 |
|---|---|---|
| `mma` | 종합격투기 | UFC, 로드FC, ONE, PFL, 프라이드 등 |
| `boxing` | 복싱 | 프로·아마추어·올림픽 |
| `kickboxing` | 킥복싱·무에타이 | K-1, 글로리, 룸피니 등 |
| `bjj` | 주짓수·그래플링 | IBJJF, ADCC, 노기 |
| `wrestling` | 레슬링 | 자유형·그레코로만·포크스타일(미국 대학) |
| `judo_sambo` | 유도·삼보 | MMA 출신 배경으로 자주 등장 |
| `general` | 격투 일반 | 여러 종목에 걸친 문화·용어·과학(감량, 부상 등) |

**주제 (topic)**: `rules`(규칙·판정) · `technique`(기술) · `history`(역사) · `people`(선수·코치·인물) · `events`(대회·명경기) · `orgs`(단체·체급 제도) · `records`(기록·통계) · `culture`(용어·밈·문화) · `korea`(국내 격투)

**난이도 (1~5)** — AI는 처음 값만 제안하고, 출시 후에는 실제 정답률로 다시 맞춘다 (§8-3).

| 단계 | 기준 | 예 |
|---|---|---|
| 1 | 격투를 거의 안 봐도 맞힘 | "복싱에서 쓰러진 선수에게 세는 숫자는 몇까지?" |
| 2 | 가끔 보는 팬 | UFC 일반 경기 라운드 구성 |
| 3 | 꾸준히 보는 팬 | 유명 기술의 원리, 주요 타이틀전 결과 |
| 4 | 코어 팬 | 체급 역사, 덜 유명한 명경기, 규칙 세부 |
| 5 | 매니아 | 세부 기록, 옛 단체, 종목 간 규칙 차이의 디테일 |

**시의성 (temporal)** — 격투 퀴즈의 가장 큰 함정은 "현 챔피언은?"처럼 시간이 지나면 틀리는 문제다.

| 종류 | 설명 | 처리 |
|---|---|---|
| `evergreen` | 시간이 지나도 변하지 않음 (과거 사실, 규칙 원리, 기술) | 기본 |
| `as_of` | 특정 시점 기준 사실 ("2026년 11월 기준 ○○ 챔피언") | 문제에 기준일 표기 필수, `review_after` 날짜 지나면 자동 재검증 큐로 |
| `rule_versioned` | 규칙 개정 가능성 있음 (통합 규칙 개정 등) | 연 1회 재검증 |

> 원칙: **MVP는 evergreen 위주(80% 이상).** "현재"를 묻는 문제는 항상 기준일을 붙인다.

**지역 (region)**: `global` / `kr` / (나중에 `jp`, `us` …). 글로벌 출시 때 국내 한정 문제는 해외 노출 비중을 낮춘다.

### 4-2. 문제 유형

| 유형 | MVP | 비고 |
|---|---|---|
| 4지선다 | ✅ | 주력 |
| OX | ✅ | 쉬운 난이도, 빠른 템포용. 단 "애매한 OX"가 많이 나오므로 검증 기준을 더 엄격히 |
| 순서 맞추기 | v1 | 연대기 (예: 단체 설립 순서) |
| 매칭 | 이후 | 기술 ↔ 종목, 선수 ↔ 별명 |
| 이미지 | 이후 | 저작권 정리 후 |

### 4-3. 초기 목표 물량

- 출시 시점: **검수 완료 문제 1,000개** (종목·난이도별 최소 수량 매트릭스로 관리), 지식카드 200개
- 이후: 하루 30~100개 순증 (게시 기준. 생성은 훨씬 많이 하고 걸러낸다)

## 5. 문제 규격 (Question Schema)

AI가 반드시 이 규격의 JSON으로 출력하고, 서버가 스키마(zod)로 검증한다. 규격을 어기면 폐기.

설계 원칙:
- **정답은 텍스트가 아니라 보기 ID로 저장** → 번역·보기 섞기와 무관하게 정답이 유지된다.
- **선수·기술·단체는 엔티티 ID로 연결** → 표기 통일, 번역, "이 선수 관련 문제" 묶기가 가능.
- **언어 독립 부분과 언어별 텍스트를 분리**.

```jsonc
{
  "id": "q_01JCX8...",                // ULID
  "version": 3,                        // 수정할 때마다 증가 (풀이 기록은 버전과 함께 저장)
  "type": "single_choice",             // single_choice | true_false | ordering
  "sport": "mma",
  "topics": ["rules"],
  "difficulty": 2,                     // AI 제안값. 출시 후 실측으로 보정
  "temporal": { "kind": "evergreen" }, // 또는 { "kind": "as_of", "as_of": "2026-11-01", "review_after": "2027-02-01" }
  "region": ["global"],
  "fact_ids": ["f_01JCX7..."],         // 이 문제가 근거로 삼는 검증된 사실
  "entity_ids": ["org_ufc"],
  "answer": { "choice_id": "b" },
  "content": {
    "ko": {
      "stem": "UFC에서 타이틀전도 메인 이벤트도 아닌 일반 경기의 라운드 구성은?",
      "choices": [
        { "id": "a", "text": "3분 3라운드" },
        { "id": "b", "text": "5분 3라운드" },
        { "id": "c", "text": "5분 5라운드" },
        { "id": "d", "text": "3분 5라운드" }
      ],
      "explanation": "UFC 일반 경기는 5분 3라운드, 타이틀전과 메인 이벤트는 5분 5라운드로 치른다. 라운드 사이 휴식은 1분이다.",
      "translation": { "status": "original" } // original | machine | reviewed
    },
    "en": { "...": "생성 시 함께 만들어 비공개 보관 (§7)" }
  },
  "sources": [
    { "url": "https://...", "title": "...", "accessed_at": "2026-11-13" }
  ],
  "provenance": {
    "pipeline_run": "run_01JCX...",
    "generator": "nvidia/nemotron-3-ultra-550b-a55b",
    "verifiers": ["k-exaone_v2.5", "google/gemma-4-31b-it"],
    "prompt_version": "gen-q-v1"
  },
  "quality": {
    "verify_score": 0.94,
    "status": "published"               // draft | review | published | retired
  }
}
```

**보기(오답) 규칙** — 문제 품질의 절반은 오답 보기에서 결정된다.
- 같은 범주에서 고른다 (선수 문제 → 같은 체급·같은 시대 선수, 수치 문제 → 그럴듯한 근처 값).
- "모두 맞다/모두 틀리다" 금지, 정답만 길거나 구체적인 보기 금지.
- 오답 중 하나라도 **"관점에 따라 정답"이 될 수 있으면 폐기**.
- 엔티티 DB가 쌓이면 오답 후보를 DB에서 뽑아 AI에게 고르게 한다 (환각 오답 방지).

## 6. AI 자동 생성 파이프라인

### 6-1. 지금 쓸 수 있는 인프라 (서버 `~/dockers/desktop-ai` 확인 결과)

| 자원 | 내용 | Fight IQ에서의 쓰임 |
|---|---|---|
| **NVIDIA Build** (키 3개 풀) | Nemotron 3 Ultra 550B, Nemotron 3.5 Super VL 120B, Gemma 4 31B 등. 키당 분당 35회, 전체 105회. 코딩(Zoo Code)과 **공유** | 사실 추출·문제 생성(Ultra), 블라인드 풀이 검증(Gemma/Super) |
| **LG K-EXAONE 2.5** (키 3개) | 키당 초당 1회, 429가 잦지만 브릿지가 재시도 처리. 한국어 강함 | 한국어 문장 다듬기, 한국어 기준 검증, 번역 검수 |
| **로컬 Ollama** (데스크톱 RTX 3060, qwen3.5:9b 등) | 데스크톱이 켜져 있을 때만. 비동기 작업(`/v1/jobs`)은 `LOCAL_CLIENTS` 전용 | 선택: 태깅, 중복 판정 같은 가벼운 일을 켜져 있을 때 몰아서 |
| **웹 검색** `GET /search` | SearXNG, 데스크톱을 깨우지 않음, `categories·language·time_range` 전달 가능 | 사실 수집의 근거 확보, 시의성 문제 재검증 |
| 브릿지 공통 | OpenAI 호환 API, 클라이언트별 API 키, 사용량 기록(`/admin/usage`), 상태(`/status`) | Fight IQ 전용 키로 붙고 사용량을 따로 본다 |

**브릿지 쪽에 필요한 설정 (desktop-ai `.env`)**
```
API_KEYS=...,fightiq:<새 키>
NVIDIA_CLIENTS=coding,admin,fightiq
EXAONE_CLIENTS=coding,admin,fightiq
# (선택) 데스크톱이 켜졌을 때 로컬도 쓰려면
LOCAL_CLIENTS=webui,fightiq
```
Fight IQ 컨테이너는 `junlab-ai` 외부 네트워크에 붙어 **내부 주소 `http://junlab-ai:8000/v1`** 로 호출한다 (Cloudflare 100초 제한과 무관). 웹 검색은 `http://junlab-ai:8000/search`.

### 6-2. 왜 "사실 먼저, 문제는 나중"인가

LLM에게 "MMA 퀴즈 10개 만들어"라고 하면 그럴듯하지만 **틀린 문제**가 섞인다. 특히 날짜, 전적, 몇 회 방어, 누가 이겼는지 같은 사실이 잘 틀린다. 퀴즈 서비스에서 정답이 틀리면 신뢰가 바로 무너진다.

그래서 두 단계로 나눈다.

```
[1단계: 사실 은행 Fact Bank]                     [2단계: 문제 은행 Question Bank]
검색 결과/출처 ──▶ 원자적 사실 추출 ──▶ 교차검증 ──▶ facts ──▶ 문제 생성 ──▶ 검증 ──▶ questions
                  "UFC 일반 경기는 5분 3R"                       (사실 1~2개로 문제 1개)
                       │
                       └──▶ 지식카드 · 해설 · 번역의 공통 원천
```

- 사실은 짧고 검증하기 쉽다 → 검증 정확도가 올라간다.
- 하나의 사실로 난이도·유형이 다른 문제를 여러 개 만들 수 있다.
- 사실이 틀린 것으로 밝혀지면 **연결된 문제를 한 번에 내릴 수 있다**.
- 사실 묶음이 곧 목표 [2]의 지식 라이브러리가 된다.

### 6-3. 파이프라인 단계

```
① 커버리지 계획  →  ② 소재·근거 수집  →  ③ 사실 추출  →  ④ 사실 검증
                                                         │
⑨ 게시 후 관리  ←  ⑧ 판정  ←  ⑦ 교차 검증  ←  ⑥ 기계 검사  ←  ⑤ 문제 생성
```

| 단계 | 하는 일 | 사용 자원 |
|---|---|---|
| ① 커버리지 계획 | 종목×주제×난이도 매트릭스에서 **부족한 칸**을 계산해 생성 지시 생성 (예: "wrestling × history × 3이 12개뿐 → 목표 60") | DB 쿼리 (AI 불필요) |
| ② 소재·근거 수집 | 주제에 맞는 검색어를 만들고 `/search`로 결과 수집, 상위 페이지 본문 읽기 | `/search` + 가벼운 모델(검색어 생성) |
| ③ 사실 추출 | 수집한 본문에서 원자적 사실 + 출처 + 시의성 태그를 JSON으로 추출. **출처 본문에 없는 내용은 금지** | Nemotron Ultra (`junlab/plan-medium`) |
| ④ 사실 검증 | 다른 모델이 출처 본문과 사실을 대조해 지지/반박/불충분 판정. 출처 2개 이상 일치하면 가산점 | EXAONE 또는 Gemma 4 31B |
| ⑤ 문제 생성 | 검증된 사실 + 규격(§5) + 난이도 기준 + 오답 규칙으로 문제 생성. ko·en 동시 출력 | Nemotron Ultra |
| ⑥ 기계 검사 | 스키마 검증, 금칙(정답 노출, 보기 중복, 길이), **중복 검사**(정규화 텍스트 해시 + Postgres `pg_trgm` 유사도 + 같은 fact_id 문제 수) | 코드 |
| ⑦ 교차 검증 | **블라인드 풀이**: 정답을 숨기고 다른 모델 2개에게 풀게 함 → 둘 다 정답과 일치해야 통과. 추가로 "정답이 둘 이상일 수 있는가 / 애매한가 / 시의성 문제인가" 체크리스트 판정. 한국어 문장 자연스러움은 EXAONE가 다듬기 | Gemma 4 31B + EXAONE |
| ⑧ 판정 | 점수로 자동 게시 / 검수 큐 / 폐기 (아래 표) | 코드 |
| ⑨ 게시 후 관리 | 정답률·신고·평가로 품질 감시, 난이도 재보정, `review_after` 도래 시 ②부터 재검증 | 코드 + 주기 작업 |

**⑧ 판정 기준 (초기값, 운영하며 조정)**

| 조건 | 결과 |
|---|---|
| 사실 검증 통과 + 블라인드 풀이 2/2 일치 + 체크리스트 이상 없음 + 주제가 `rules/technique/culture` | 자동 게시 (단, 출시 전 시드 단계에서는 전부 검수) |
| 위와 같지만 주제가 `records/people/events` (사실 오류 위험 높음) 또는 `as_of` | 검수 큐 |
| 블라인드 풀이 1/2 | 검수 큐 (문제가 애매할 가능성) |
| 블라인드 풀이 0/2 또는 사실 검증 반박 | 폐기 (사유 기록 → 프롬프트 개선 자료) |

> 검수 큐로 간 문제는 사람 대신 **AI 검수 위원회**(§6-7)가 판정한다.

### 6-7. AI 검수 위원회 (사람 검수 대체)

시드 1,000문제를 포함해 검수는 AI에게 맡긴다. 대신 생성 단계보다 **더 엄격하고, 서로 다른 모델 여럿이 독립적으로** 보게 한다.

- **위원 구성**: 생성 모델과 다른 계열 모델 3개 (모델 선정은 샘플 실험 결과 참고, `docs/샘플문제_평가.md`)
- **위원 1·2 (블라인드 풀이)**: 정답을 숨기고 풀이 + 애매함·사실오류 여부
- **위원 3 (근거 대조 심사)**: 정답·출처 본문을 함께 보고 "출처가 정답을 직접 뒷받침하는가", "오답 중 정답이 될 수 있는 것이 있는가"를 판정
- **만장일치일 때만 게시**. 한 명이라도 문제를 제기하면 사유와 함께 재생성(최대 2회) → 그래도 안 되면 폐기
- **사람의 역할**: 매주 게시 문제 무작위 20개 표본 확인 + 신고 건 처리. 표본 오류율이 1%를 넘는 칸(종목×주제)은 자동 게시를 멈추고 기준을 올린다
- 출시 후에는 사용자 신고·정답률 이상 감지(§9)가 마지막 안전망 역할

### 6-4. "무료 한도가 남을 때만" 돌리는 스케줄러

브릿지 기준으로 NVIDIA 한도는 **토큰이 아니라 키당 분당 요청 수(RPM)** 이고, 코딩 도구와 같은 키 풀을 쓴다. 그래서 "남는 토큰"보다는 **"남는 요청 여유"를 쓰는 저우선순위 작업**으로 설계한다.

- **시간대**: 기본 01:00~08:00 KST에 집중 (코딩 사용이 적은 시간). 낮에는 소량만.
- **여유 확인**: 작업 단위마다 `GET /status`의 `nvidia.keys`(키별 최근 60초 전송 수)를 보고, 전체 사용률이 50% 미만일 때만 다음 호출. 넘으면 대기.
- **자체 상한**: Fight IQ 워커는 NVIDIA 분당 최대 15회, EXAONE 초당 1회 이하로 스스로 제한. 429를 받으면 지수 백오프.
- **일일 상한**: 하루 생성 후보 수와 게시 수에 상한 (예: 후보 500 / 게시 100). 물량보다 품질이 병목이므로.
- **세션 고정**: 파이프라인 실행 단위로 `X-Session-Id`를 붙여 브릿지의 키 고정 기능을 활용.
- **추적**: 단계별 호출 수·토큰·통과율을 `generation_runs`에 기록하고, 브릿지 `/admin/usage`의 `fightiq` 행과 대조.
- **중단돼도 서비스는 계속된다**: 무료 API 정책이 바뀌어도 이미 쌓인 문제은행으로 운영 가능. 생성은 "보충" 역할.

> 📌 **브릿지 개선 제안** (desktop-ai 쪽, 선택): `NVIDIA_LOW_PRIORITY_CLIENTS=fightiq` 설정을 추가해, 이 클라이언트는 키 사용률이 일정 수준 이하일 때만 슬롯을 받도록 하면 Fight IQ가 코딩 작업을 절대 방해하지 않는다. Fight IQ 워커의 자체 제한보다 확실한 방법.

**대략적인 처리량 추정**: 문제 1개당 평균 4~6회 호출 (사실 추출·검증은 여러 문제가 공유). 야간 7시간 × 분당 15회 ≈ 6,300회 → 하룻밤 **후보 1,000개 이상** 가능. 즉 AI 처리량은 충분하고, 실제 병목은 **검수 인력**과 **품질 기준**이다.

### 6-5. 프롬프트 관리

- 프롬프트는 코드 저장소에 파일로 두고 버전을 붙인다 (`prompts/gen-question.v1.md`). 문제마다 어떤 버전으로 만들어졌는지 기록.
- 폐기·신고 사유를 주기적으로 모아 프롬프트를 개선 → 버전별 통과율 비교.
- 시스템 프롬프트에 포함할 것: 문제 규격, 난이도 정의, 오답 규칙, 금지사항(출처 없는 수치, 루머, 선수 비하, 사생활), 한국어 표기 규칙(§7-3 용어집 일부 주입).
- 출력은 JSON만. 생각(reasoning) 과정은 저장하지 않는다.

### 6-6. 생성 장르 다양화

같은 사실이라도 질문 각도를 바꿔 다양성을 확보한다. 생성 지시에 "각도"를 함께 넘긴다.

- **정의형**: "이 기술의 이름은?" / **원리형**: "이 서브미션이 압박하는 관절은?"
- **비교형**: "MMA와 복싱의 판정 기준 차이로 옳은 것은?"
- **역사형**: "가장 먼저 생긴 단체는?" / **인물형**: "이 별명을 가진 선수는?"
- **상황형**: "경기 중 이런 상황에서 심판이 내리는 판정은?" (규칙 이해에 가장 좋음)
- **숫자형**: 체급 한계 체중, 라운드 시간 (단위 주의, §7)

## 7. 다국어(글로벌) 전략

### 7-1. 원칙: 번역을 "나중 작업"이 아닌 "구조"로 해결

나중에 한국어 문제 수천 개를 통째로 번역하면 비용·품질 문제가 커진다. 처음부터 구조로 대비한다.

| 장치 | 효과 |
|---|---|
| 정답 = 보기 ID | 번역해도 정답이 깨지지 않음 |
| 선수·기술·단체 = 엔티티 ID + 언어별 표기 사전 | "하빕 누르마고메도프 / Khabib Nurmagomedov"를 한 곳에서 관리, 표기 통일 |
| 사실(Fact)은 영어 원문 + 출처로 저장 | 출처 대부분이 영어, 모델 정확도도 영어가 높음. 어느 언어로든 다시 문제화 가능 |
| **생성할 때 ko·en을 함께 만든다** (en은 비공개 보관) | 글로벌 오픈 시 번역 비용이 거의 없고, en 버전은 지금도 검증 대조용으로 쓸모 있음 |
| 문제마다 `translatable` / `region` 표시 | 말장난·국내 한정 문제는 번역 대상에서 제외하거나 지역 노출 조절 |
| UI 문자열은 처음부터 i18n 파일로 분리 | 화면 번역은 언제든 가능 (`next-intl`, URL `/ko`, `/en` 구조만 미리) |

### 7-2. 번역 파이프라인 (글로벌 오픈 시)

```
원문(ko) + 영어 초안(en, 생성 시 동시 작성)
   → 용어집 주입 번역/보정 (Nemotron 또는 Gemma)
   → 블라인드 풀이 재사용: 번역문만 보고 다른 모델이 풀어 정답 일치 확인
   → status: machine (노출 가능, "기계 번역" 표시 없이)
   → 해당 언어 사용자 신고·정답률 이상 시 검수 큐
   → status: reviewed
```

- 블라인드 풀이는 "번역 때문에 의미가 바뀌어 정답이 달라진 경우"를 잡는 데 매우 효과적이다.
- 언어별로 정답률이 크게 차이 나는 문제는 번역 품질 문제일 가능성이 높으므로 자동 경고.

### 7-3. 용어집·표기 규칙 (지금부터 쌓기)

- **엔티티 사전**: 선수/단체/대회/기술마다 언어별 표기 + 별칭. 한국어는 **국내 중계·커뮤니티에서 통용되는 표기 우선** (예: 공식 외래어 표기법보다 실제 쓰는 이름), 별칭으로 다른 표기도 저장해 검색에 활용.
- **기술 용어**: 리어 네이키드 초크, 암바, 트라이앵글 초크 … 영어 음차가 표준인 것과 한국어 번역어가 통용되는 것(예: 유도·레슬링 용어)을 구분해 규칙으로 고정.
- **단위**: 체급은 lb·kg 병기 (국내는 kg 먼저), 숫자형 문제는 단위 표기를 구조화해서 로케일별로 렌더링.
- 용어집은 생성·번역 프롬프트에 해당 문제에 필요한 항목만 주입.

### 7-4. 글로벌 확장 시 콘텐츠 전략

- 1차 영어권: 영어 사용자는 국내 한정 문제(로드FC 등) 노출 비중을 낮추고, 대신 글로벌 문제 비중을 높인다.
- 2차 후보: 일본(격투 시장 큼, 프라이드·RIZIN 역사), 브라질(주짓수), 태국(무에타이) → 지역 전용 콘텐츠를 지역별로 생성.

## 8. 기술 설계

### 8-1. 스택 (서버의 다른 서비스들과 통일)

`hamexam-team`과 같은 스택을 써서 배포·운영 방식을 재사용한다.

| 영역 | 선택 |
|---|---|
| 웹 | Next.js 16 (App Router) · shadcn/ui · Tailwind CSS 4 · `next-intl` |
| DB | PostgreSQL 17 + Drizzle ORM (`pg_trgm` 확장으로 중복 검사) |
| 인증 | 비회원 우선 + 구글 로그인(Firebase, hamexam 방식 재사용). 세션 쿠키는 자체 발급·DB 저장. 카카오는 이후 |
| 도메인 | `fightiq.runvia.app` |
| 생성 워커 | 같은 저장소의 Node.js(TypeScript) 별도 컨테이너 — Drizzle 스키마·zod 규격 공유. 작업 큐는 Postgres 테이블 (`FOR UPDATE SKIP LOCKED`) |
| AI 호출 | OpenAI SDK → `http://junlab-ai:8000/v1` (fightiq 키) |
| 배포 | Docker Compose (web · worker · db) → nginx → Cloudflare. 서버 경로 `~/dockers/fight-iq` (이미 빈 디렉터리 있음) |
| 공유 이미지 | Next.js OG 이미지 생성 (결과카드) |

```
          사용자 ──▶ Cloudflare ──▶ nginx ──▶ [web: Next.js] ──▶ [Postgres]
                                                                    ▲
                    [worker] ── 스케줄러 → 파이프라인 ─────────────┘
                        │
                        └── junlab-ai 네트워크 ──▶ desktop-ai api ──▶ NVIDIA / EXAONE / SearXNG / (로컬 Ollama)
```

### 8-2. 데이터 모델 (주요 테이블)

| 테이블 | 내용 |
|---|---|
| `entities`, `entity_names` | 선수·단체·대회·기술·체급 / 언어별 표기·별칭 |
| `facts`, `fact_sources` | 원자적 사실(영어 원문 + 한국어), 시의성, 검증 상태 / 출처 URL·접근일 |
| `questions` | 언어 독립 부분 (종목·주제·난이도·정답 ID·상태·버전) |
| `question_texts` | 언어별 문항·보기·해설·번역 상태 |
| `question_facts`, `question_entities` | 연결 테이블 |
| `knowledge_cards` | 지식 라이브러리 카드 (여러 fact를 묶어 읽기 좋게 쓴 글) |
| `quiz_sets` | 데일리 세트, 이벤트 세트, 코스 |
| `users`, `sessions`, `auth_accounts` | 회원 (카카오/구글) |
| `attempts`, `answers` | 풀이 기록 (문제 버전 포함), 응답 시간 |
| `ratings` | 사용자 레이팅·벨트, 문제 레이팅 |
| `reports`, `question_feedback` | 신고, 좋아요/싫어요 |
| `generation_runs`, `generation_items` | 파이프라인 실행 기록, 단계별 결과·사유·호출 수 |
| `glossary` | 용어집·표기 규칙 |

### 8-3. 레이팅과 난이도 자동 보정

사용자와 문제를 둘 다 레이팅을 가진 "선수"로 보고, 풀 때마다 **Elo 방식**으로 서로의 레이팅을 갱신한다 (맞히면 사용자↑ 문제↓).
- 사용자 레이팅 → **Fight IQ 점수와 벨트**
- 문제 레이팅 → **실제 난이도**. 일정 수 이상 풀린 문제는 AI가 붙인 난이도 대신 실측 난이도로 교체
- Fight IQ 테스트의 적응형 출제에도 그대로 사용

### 8-4. 관리자 기능

- 검수 큐: 문제 + 근거 사실 + 출처 + 검증 모델들의 판정 사유를 한 화면에. 단축키로 승인/수정/폐기
- 신고 처리, 문제·사실 수정 (수정 시 버전 증가)
- 사실 무효화 → 연결 문제 일괄 비공개
- 파이프라인 대시보드: 일별 생성·통과·폐기 수, 단계별 폐기 사유 Top, 커버리지 매트릭스 빈칸

## 9. 운영·품질 정책

- **오류 신고 처리 목표**: 신고 3건 이상 또는 "정답 틀림" 신고 1건이 신뢰도 높은 사용자에게서 오면 즉시 임시 비공개 → 검수
- **정답률 이상 감지**: 난이도 대비 정답률이 비정상(예: 난이도 1인데 정답률 20%) → 정답 오류·애매함 의심으로 검수 큐
- **시의성 재검증**: `review_after` 도래 문제는 매일 배치로 검색 재확인
- **콘텐츠 가이드라인**: 선수 비하·사생활·도박(배팅) 유도·루머 금지. 부상·사망 관련은 사실 위주로 신중하게
- **저작권·상표**: 단체 로고·선수 사진·중계 영상 캡처 사용 안 함. 선수 이름·단체 이름을 사실 서술에 쓰는 것은 문제없음. 단체와 제휴로 오인될 표현("공식" 등) 금지

## 10. 성장 전략 (국내)

1. **결과카드 공유**: Fight IQ 테스트·데일리 결과를 인스타 스토리/카톡용 이미지로. 가장 중요한 유입 장치
2. **대회 연동 이벤트**: 큰 대회(UFC 넘버링, 로드FC, 한국 선수 출전 경기) 주간에 프리뷰 퀴즈 → 커뮤니티에 링크
3. **커뮤니티 시딩**: 격투 커뮤니티(디시 격투기 갤러리, 에펨코리아 격투 게시판, 네이버 격투 카페)에 "Fight IQ 테스트" 결과 놀이로 진입
4. **체육관 연계**: 주짓수·MMA 체육관에 "관원 랭킹" 기능 제안 (입소문 + B2B 가능성)
5. **격투 유튜버·인스타 계정 협업**: 구독자 대상 퀴즈 이벤트 (출제자 크레딧)
6. **SEO**: 지식카드·용어사전 페이지를 검색 친화적으로 ("리어 네이키드 초크란" 등). 학습 콘텐츠가 검색 유입원이 됨

## 15. 디자인 방향

- **공통 컴포넌트**: shadcn/ui(Base UI) — 버튼·카드·다이얼로그·탭·토스트 등 기본 부품을 그대로 쓰고, 화면별로 새로 만들지 않는다. hamexam-team과 같은 방식이라 운영 노하우를 재사용.
- **Fight IQ 정서는 토큰과 전용 컴포넌트 몇 개로 낸다**: shadcn 기본값은 차분한 업무용 톤이라 그대로 쓰면 격투 서비스 느낌이 나지 않는다. 색·폰트·모서리·그림자 토큰만 바꾸고, 퀴즈 전용 컴포넌트(라운드 표시, 보기 버튼, 판정 연출, 벨트 배지, 결과카드)는 shadcn 부품을 조합해 공통 컴포넌트로 만든다.
- **톤**: 어두운 배경(링·옥타곤 조명 느낌) 기본 + 라이트 모드 지원, 강조색 1개(레드 계열), 승리·정답은 골드 계열. 굵고 좁은 제목 폰트 + 읽기 편한 본문 폰트(한글은 Pretendard 계열).
- **모바일 우선**: 한 손 엄지로 보기를 누르는 레이아웃, 보기 버튼은 크게.
