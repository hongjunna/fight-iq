# 샘플 문제 생성 실험 — 품질 평가와 모델 추천

> 실험일 2026-11-13 · 주제 5개 × 생성 모델 5종 = 25건, 생성된 문제마다 다른 모델 2개가 블라인드 풀이
> 스크립트·원본 결과: 서버 `~/fightiq-lab/` (`gen_test2.py`, `r2.jsonl`)

## 결론

**실사용 가능하다. 단, 생성된 그대로 게시하면 안 되고 검증 단계를 더 붙여야 한다.**

- 정상 출력 16건 중 **정답(키) 자체가 맞은 문제는 14건(88%)**, 문제·보기·해설까지 **흠 없이 바로 쓸 수 있는 문제는 10건(63%)**, 사소한 표현만 고치면 되는 문제까지 합치면 13건(81%).
- 틀린 3건은 모두 **블라인드 풀이로는 걸러지지 않는 유형**이었다. 블라인드 풀이는 정답 키만 확인하고, 해설 속 세부 사실이나 규칙 개정 이력이 틀린 것은 잡지 못한다. 그래서 파이프라인에 **해설 사실 대조**와 **출처 등급** 단계를 추가해야 한다 (아래 §4).
- 모델 응답 안정성 차이가 컸다. 이날 NVIDIA의 Gemma·DeepSeek는 대부분 300초 시간 초과였다.

## 4. 파이프라인에 추가할 것

1. **해설 사실 대조 (근거 대조 심사 위원)** — Super가 해설을 문장 단위로 쪼개 각 문장이 출처 본문에 있는지 확인한다. 출처에 없는 문장은 지우거나 문제를 폐기한다. 위 오류 대부분이 여기서 걸린다.
2. **출처 등급** — 1등급: 단체·연맹 공식(ufc.com, uww.org, ibjjf.com, olympics.com 등), Wikipedia / 2등급: 주요 격투 매체(ESPN, MMA Fighting, Sherdog 기사 등) / 불가: 커뮤니티·SNS·영상. **사실 하나에 1등급 1개 또는 2등급 2개 이상**이어야 사실 은행에 들어간다.
3. **규칙 개정 이력·"최초" 같은 주제는 `rule_versioned`로 표시**하고 1등급 출처가 없으면 폐기한다.
4. **엔티티 사전 주입** — Wikidata 한국어 이름 + 국내 통용 표기를 프롬프트에 넣어 표기를 통일한다 (레너드 가르시아, 럼블 인 더 정글).
5. **금칙 문구 필터** — "근거", "제시된", "검색 결과" 같은 메타 표현은 기계 검사에서 걸러 낸다.
6. **호출 운영** — 호출 하나당 제한 시간 120초, 실패하면 같은 역할의 예비 모델로 한 번만 대체 (생성: Ultra → Super, 풀이: DeepSeek → Gemma). 생성 프롬프트는 "해설은 facts 에 있는 내용만"으로 강화한다.

## 4-1. 개선 파이프라인(v3) 재실험 결과 — 2026-11-13

§4의 1~5번(페이지 본문 읽기 + 출처 등급 + 원문 인용 코드 검증 + 이름 사전 + 메타 문장 필터 + 해설 문장 대조)을 넣고 **주제 20개**로 다시 돌렸다. 기록·인물·규칙 개정처럼 틀리기 쉬운 주제를 일부러 넣었다. 결과는 제가 하나씩 사실 확인했다. (서버 `~/fightiq-lab/pipeline_v3.py`, `v3.jsonl`)

| 지표 | v2 (이전) | **v3** |
|---|---|---|
| 정답 키가 맞은 비율 | 14/16 (88%) | **15/15 (100%)** |
| 해설 속 사실 오류 | 3건 | **0건** |
| 이름 표기 불일치 | 3건 | **0건** |
| 메타 문장 노출 | 1건 | **0건** |
| 정답이 둘로 읽힐 수 있는 문제 | 0건 | 1건 (아래 t09) |
| 생산율 (주제 → 문제) | — | 15/20 (게시 가능 13, 검수 대기 2) |
| 문제당 시간 | 14초~5분 | 3~7분 (호출 6~7회) |

**해설 문장 대조가 실제로 일했다.** 근거 없는 해설 문장 7개를 지웠다. 예: "고도칸 건물 층수는 후대의 일이며 올림픽 채택은 훨씬 나중" (t18), "국제 삼보 연맹·IOC는 당시 채택하지 않았다" (t19). 지워진 문장 중 하나("타이슨은 20세 4개월 22일")는 사실 맞는 말이었지만 출처에 없어서 지워졌다. 보수적으로 동작하는 것이 맞는 방향이다.

**사람이 확인해서 찾은 문제 (v3 에서도 남은 것)**

| 주제 | 문제 | 원인 → 대책 |
|---|---|---|
| t09 파퀴아오 | "최초이자 유일한 **체급 관련** 기록은?" 정답은 8체급이지만, 오답 보기 "4대 글래머 디비전 석권"·"4개 시대에 걸친 챔피언"도 현실에서는 파퀴아오의 실제 기록이라 정답처럼 읽힌다 | 검증이 '사실 목록 안'만 봐서 **오답이 현실에선 참인지**는 못 봄 → 블라인드 풀이 위원에게 "현실에서 참인 오답이 있는가"를 함께 묻는다 |

대책: ① 검색과 별개로 **위키백과 문서를 항상 1개 이상** 직접 찾아 읽는다 ② 2등급 목록 보강 (NPR, NBC·CBS·ABC News, Yahoo Sports 등) ③ **주제 위험도별 기준** — 기술·용어(바뀌지 않고 틀려도 피해 작음)는 서로 다른 3등급 도메인 3곳 일치도 인정, 기록·인물·규칙 개정은 지금처럼 엄격하게.

**결론**: 세 단계를 넣자 **사실 오류는 사라졌고**(해설 오류 3 → 0, 표기 3 → 0), 남은 위험은 "오답이 현실에선 참인 경우" 하나로 좁혀졌다. 위 대책(블라인드 위원에게 오답 진위 질문 + 위험도별 출처 기준)을 넣으면,
- **자동 게시 가능**: 규칙(개정 이력 제외)·기술·역사·단체 — 1등급 출처가 있는 칸부터
- **검수 대기 유지**: 인물·기록·`as_of`(시점 의존) — 매주 표본 확인으로 오류율 1% 미만이 확인되면 자동 게시로 전환
