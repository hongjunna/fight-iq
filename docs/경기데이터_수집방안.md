# 전 세계 격투 경기·이벤트 데이터 수집 방안

> 조사일 2026-11-13 · 목적: 이벤트 시즌 퀴즈, 시의성 문제(`as_of`) 재검증, 사실 은행(Fact Bank) 소재 공급

## 결론 요약

**"한 군데서 다 받는 무료 API"는 없다.** UFC는 데이터가 넘치지만 로드FC·ONE·글로리·IBJJF·레슬링은 정형 API가 거의 없다. 그래서 소스를 3단으로 쌓고, 정형 데이터가 없는 곳은 **우리 검색(SearXNG) + AI 추출**로 메운다.

| 층 | 소스 | 비용 | 용도 |
|---|---|---|---|
| **1. 뼈대** | Wikipedia + Wikidata (MediaWiki API) | 무료, 공개 라이선스 | 역사·과거 대회·선수 정보, **다국어 표기 사전** |
| **2. 빠른 일정·결과** | ESPN 비공식 JSON | 무료 (비공식) | UFC·PFL·KSW·RIZIN 등 다가오는 대진, 결과 |
| **3. 롱테일** | 공식 사이트 + SearXNG 검색 → AI 추출 | 브릿지 무료 한도 | 로드FC, ONE, 글로리, IBJJF, UWW 등 |
| (선택) 유료 | UFCalendar API 등 | 월 $19~ | 안정성이 필요해질 때 |

## 1층 — Wikipedia / Wikidata (가장 중요)

- **영문 위키백과**에는 UFC 넘버링·파이트나이트마다 대회 문서가 있고 대진·결과 표가 정형화돼 있다. 대회 직후 빠르게 갱신된다.
- **한국어 위키백과**에도 로드FC 대회 문서가 연도별로 있다 (확인: "2011~2015 로드 FC 대회" 등).
- **Wikidata**는 선수·단체·대회를 ID로 묶고 언어별 이름(label)을 준다. 예: 정찬성 = `Q498065`. 기획서 §7의 **엔티티 사전 + 번역 문제를 상당 부분 이걸로 해결**할 수 있다. 한국어 표기, 영어 표기, 별칭을 한 번에 받는다.
- 접근: `https://{ko|en}.wikipedia.org/w/api.php`, `https://www.wikidata.org/w/api.php`. 무료이며 User-Agent에 서비스 이름을 밝히고 요청 속도를 지키면 된다.
- 라이선스: 본문 텍스트는 CC BY-SA라 **문장을 그대로 복사하면 안 된다.** 사실만 뽑아 쓰고 문제·해설은 우리가 새로 쓴다. 출처 링크는 단다.

## 2층 — ESPN 비공식 JSON

- `https://site.api.espn.com/apis/site/v2/sports/mma/{league}/scoreboard` (확인 결과)
  - `ufc` → 이번 주 대회 "UFC 334: Gane vs. Hokit" (2026-11-14), 13경기 대진과 상태(Scheduled/Final)
  - `pfl`, `bellator`, `lfa`, `ksw`, `rizin` → 응답 정상 (200). `one`은 400 (미지원)
  - 날짜 파라미터로 과거 결과도 조회할 수 있다고 알려져 있다 (`?dates=YYYYMMDD`, 실사용 전 확인 필요)
- ESPN 웹·앱이 쓰는 엔드포인트로, 오래 안정적이었다는 평이 많다. 다만 **공식 문서가 없어 예고 없이 바뀔 수 있다.**
- 사용 원칙: 하루 몇 번만 조회하고 결과는 우리 DB에 캐시한다. 실패하면 3층(검색+AI)으로 대체한다. 화면에 ESPN 데이터를 그대로 보여 주지 않고 **퀴즈 소재와 검증용으로만** 쓴다.

## 3층 — 검색 + AI 추출 (롱테일 단체)

정형 API가 없는 단체용이다. 이미 있는 브릿지 자원으로 만든다.

```
일정 감지 → 검색 → 페이지 읽기 → AI 구조화 추출 → 2개 출처 교차 확인 → events/bouts 테이블
```

1. **대상 목록**(설정 파일): 로드FC, ONE, 글로리, RIZIN, K-1, IBJJF 메이저(월드·팬암·유러피언), ADCC, UWW 세계선수권·올림픽, 복싱 4대 기구 타이틀전
2. **검색**: 브릿지 `/search`로 `"ROAD FC 07x 결과"`, `"ONE Fight Night results"` 등을 조회 (`time_range=week`로 최근 것만)
3. **추출**: 가벼운 모델(Gemma 4 31B 또는 Nemotron Super)이 페이지 본문에서 `{event, date, venue, bouts:[{red, blue, weight_class, winner, method, round, time}]}` JSON을 뽑는다
4. **교차 확인**: 서로 다른 출처 2개의 추출 결과가 일치하는 경기만 `confirmed`. 하나만 있으면 `unconfirmed`로 저장하고 퀴즈 소재로 쓰지 않는다
5. 선수 이름은 Wikidata ID에 연결해 표기를 통일한다

부담은 작다. 대회는 주말에 몰려 있으므로 **월요일 새벽에 한 번 몰아서** 돌리면 된다.

## 피해야 할 소스

| 소스 | 이유 |
|---|---|
| **BoxRec** 스크래핑 | 2018년부터 약관으로 소프트웨어를 이용한 데이터 추출을 금지한다. 비공식 래퍼 라이브러리들도 이 약관을 어기게 된다 |
| Sherdog·Tapology **대량 수집** | 공식 API가 없고 약관 확인이 필요하다. 한국 저작권법은 데이터베이스 제작자를 보호하므로(DB의 상당 부분을 복제하는 행위) 통째로 긁어 오는 건 위험하다. 개별 사실 확인용 출처 링크로만 쓴다 |
| Apify 같은 제3자 스크래퍼 | 결국 원 사이트 약관 문제를 사용자가 떠안는다 (각 스크래퍼 설명에도 그렇게 적혀 있다) |

경기 결과 같은 **개별 사실 자체는 보호 대상이 아니다.** 문제는 남의 데이터베이스를 체계적으로 복제하는 것이다. 우리 방식(여러 출처에서 사실을 확인하고 문장은 새로 쓰기)은 이 위험을 피한다.

## (선택) 유료 API — 나중에

| 서비스 | 내용 |
|---|---|
| UFCalendar | UFC·PFL·OKTAGON·BKFC·RIZIN 결과·통계. 월 $19 (3만 요청)부터. 하루 체험만 있고 무료 플랜은 없다는 안내와 월 500회 무료라는 안내가 엇갈림 |
| Sportradar, SportsDataIO | 기업용 MMA 피드. 비싸지만 공식 라이선스 |
| BALLDONTLIE MMA | UFC 위주, 다른 단체 데이터는 매우 적음 |

서비스가 커져서 실시간 결과 연동(예: 경기 직후 퀴즈)이 필요해지면 그때 검토한다.

## Fight IQ에 붙이는 방식

- 테이블 추가: `events`, `bouts`, `event_sources` (기획서 §8-2에 추가 예정)
- **이벤트 시즌 퀴즈**: ESPN·검색으로 다음 주 대진을 받아 출전 선수 관련 사실을 Wikipedia에서 모으고 → 프리뷰 퀴즈를 자동 생성한다
- **시의성 재검증**: 챔피언이 바뀌면(`bouts`에 타이틀전 결과가 들어오면) 해당 체급 `as_of` 문제를 자동으로 재검증 큐에 넣는다
- **사실 은행 공급**: 과거 대회 표 → "누가 몇 라운드에 무엇으로 이겼나" 같은 원자적 사실로 바로 변환된다. 생성 AI가 지어낼 여지가 줄어든다
